================================================================================
VALIDATION QUERIES
================================================================================

Cache Status:
  SELECT COUNT(*) FROM wallet_analysis_state;
  SELECT COUNT(*) FROM wallet_scan_metrics;

Fingerprint Status:
  SELECT COUNT(*) FROM wallet_fingerprints;
  SELECT COUNT(*) FROM fingerprint_clusters;

Cache Hit Rate:
  SELECT
    SUM(CASE WHEN scan_type = 'cached_skip' THEN 1 ELSE 0 END) as hits,
    COUNT(*) as total,
    ROUND(100.0 * SUM(...) / COUNT(*), 1) as rate_pct
  FROM wallet_scan_metrics
  WHERE created_at >= datetime('now', '-24 hours');

Fingerprint Impact:
  SELECT
    skip_policy,
    COUNT(*) as cluster_count,
    SUM(wallet_count) as total_wallets
  FROM fingerprint_clusters
  GROUP BY skip_policy;

Credits Saved Estimate:
  SELECT
    SUM(CASE WHEN skip_policy = 'skip' THEN wallet_count * 2 ELSE 0 END) +
    SUM(CASE WHEN skip_policy = 'shallow' THEN wallet_count * 1 ELSE 0 END)
    as pages_avoided,
    (SUM(...)) * 100 as credits_saved
  FROM fingerprint_clusters;

================================================================================
TROUBLESHOOTING
================================================================================

Cache hit rate stuck at 0%:
  → Check RESCAN_INTERVAL_SECONDS in wallet_cache_production.py
  → Verify analyze_funders_batch() is being called
  → Check [CACHE] logs for errors

No fingerprints appearing:
  → Verify apply_fingerprint_after_first_page() is called after first page fetch
  → Check [FINGERPRINT] logs
  → Query: SELECT COUNT(*) FROM wallet_fingerprints;

No clusters forming:
  → Clusters need 5+ wallets with same fingerprint hash
  → Check: SELECT fingerprint_hash, COUNT(*) FROM wallet_fingerprints GROUP BY fingerprint_hash;
  → Clusters will form naturally over 7-14 days

Too many wallets marked skip:
  → Lower CONFIDENCE_THRESHOLD_HIGH in wallet_fingerprint_cache.py
  → Or manually update: UPDATE fingerprint_clusters SET skip_policy = 'shallow';
