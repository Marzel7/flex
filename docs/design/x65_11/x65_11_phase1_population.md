## Notes on evidence used

- **Creator**: `wt_attribution_outcomes.evidence_json.creator` /
  `wt_watchtower_launches.creator_wallet`, whichever field the live API
  response's `creator` value derives from.
- **Treasury**: read from `wt_active_subprov_sessions.treasury_wallet`
  (the most recent session row for each launch's resolved
  sub-provider), cross-checked against `wt_confirmed_treasuries`.
- **Sub-provider**: `campaign_evidence.subprov_wallet`, the same field
  `src/ops/campaign_classification.py` resolves and displays.
- **Funding Origin**: per X65.1 Phase 1's established finding, this
  equals Topology for this population — confirmed by direct comparison
  (not assumed) in Phase 5/6 below.
- **Operation Attribution**: two independent fields exist in the live
  data — `campaign` (X65.7, this task's entry criterion, all 19 by
  definition) and the separate, older `operation_id`/`is_watchtower`
  fields (linked only through an already-confirmed treasury →
  `wt_ops_v2_wallets` join, X65.1). Only **4 of 19 (21%)** have a
  confirmed `operation_id=WATCHTOWER` — this is reported as a distinct
  fact, not conflated with Campaign membership.
