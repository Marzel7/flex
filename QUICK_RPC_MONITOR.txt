✅ Normal Background Scan (auto_scan_creators=ON):
   Every 1-2 seconds:
   - getSignaturesForAddress (10 credits)  → source: creator_outgoing_extractor
   - helius_enhanced_transactions_batch (100 credits) → source: creator_outgoing_extractor

⚠️  Manual API Call:
   Sudden burst of helius_enhanced_transactions_batch calls
   source: main or creator_outgoing_scheduler

⚠️  Unknown Source (code issue):
   RPC calls showing source_file='unknown'
   Action: Check which endpoint/module is making the call

🔴 STOP Signal:
   If auto_scan_creators=OFF but calls still appear:
   → Calls are from manual API buttons, not background job
   → This is expected behavior (API endpoints always work)

KEY METRICS EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

getSignaturesForAddress:
  - Gets transaction signatures for a wallet
  - 10 credits each
  - Made once per creator per scan cycle
  - From: creator_outgoing_extractor background job

helius_enhanced_transactions_batch:
  - Parses transaction details in batch (up to 100 transactions per call)
  - 100 credits each
  - Made repeatedly as signatures are processed
  - From: creator_outgoing_extractor or main (API)

source_file:
  - Tells which Python module/file made the RPC call
  - creator_outgoing_extractor = background job
  - main = API endpoint
  - unknown = code not properly attributed (bug)

status_code:
  - 200 = successful, billable by Helius
  - Other = failed/retry, may still be counted

Monitor shows no activity?
  1. Check listener running: ps aux | grep pumpfun_curve_listener
  2. Check database: sqlite3 flex_complete_database.db "SELECT COUNT(*) FROM rpc_metrics;"
  3. Wait a moment (first scan takes time)

Metrics differ from Helius?
  1. Local metrics count ALL attempts (retries, failures)
  2. Helius bills only successful (status_code=200)
  3. View successful only: sqlite3 ... "WHERE status_code = 200"

Unknown source_file appearing?
  1. Some code path not properly recording source_file
  2. Check recent code changes
  3. Fix: Pass source_file parameter to record_request()

Database locked?
  1. Try again (other process releasing lock)
  2. Close VSCode connection if open
  3. Use timeout: sqlite3 -cmd ".timeout 5000" ...
