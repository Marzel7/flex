# PSI0F-D immutable-summary adapters

PSI0F-D adds a fixture-qualified byte boundary in front of the unchanged
PSI0F-B pure known-behaviour projection. The boundary accepts only injected
representations of the exact immutable PSI0E three-file envelope bundle and
the exact EB0.4 five-file operational-family bundle. It performs no filesystem,
database, network, service or configuration access.

Each adapter verifies the exact file set, canonical JSON bytes, hashes, bundle
identity, contract lineage, provenance, accounting and authority before it
derives the narrow synthetic schema already accepted by PSI0F-B. PSI0E retains
only global five-surface availability and missingness accounting. EB0.4 retains
only platform-operation roles, nomination states, supporting fact identities,
shared edge/mechanism/temporal descriptors and aggregate quality, completeness
and conflict information.

The two production-derived provenance classes remain separate. The adapter
does not create an operation-specific PSI0E relationship and the PSI0F-B core
continues to reject cross-layer joins, topology-only support, attribution,
ranking, policy, selection and authority expansion. The existing fixture-only
PSI0F-B entry point is unchanged.

Qualification uses synthetic ephemeral bundles only. Applying these adapters
to retained immutable bundles, creating a real operational surface, integrating
or deploying a consumer, Evidence modes, production activation and EB2 each
remain separately gated.
