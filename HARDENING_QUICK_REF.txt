POOL DETECTOR HARDENING: QUICK REFERENCE CARD
================================================================================

PROBLEM
  Token pool not detected → Pool detection logs are opaque
  "No AMM-owned pool found in 25 accounts" tells us NOTHING about why

SOLUTION
  Add 7 phases of hardening + debugging to make failures diagnosable

================================================================================
THE 7 PHASES
================================================================================

Phase 1: ACCOUNT KEY NORMALIZATION (5 min)
  Add _normalize_account_key() helper
  Handles: strings, dicts with "pubkey", dicts with "address"

Phase 2: TRANSACTION SHAPE LOGGING (5 min)
  Log: tx_version, base_keys, writable_loaded, readonly_loaded, has_lookups
  Example: [POOL_DETECT] tx_version=None base_keys=25 writable_loaded=0 readonly_loaded=0 total=25

Phase 3: PER-ACCOUNT DEBUG LOGGING (10 min)
  For each account: log index, owner, data_len, amm_match
  Behind POOL_DETECTOR_DEBUG flag (optional verbose output)

Phase 4: AMM CANDIDATE VALIDATION (10 min)
  Add AMMDataLengths class with minimum pool state sizes
  Reject: owner in AMM but data_len < expected
  Prevents: false positives from helper PDAs

Phase 5: FALLBACK DISCOVERY PATH (20 min)
  New method: _discover_pool_via_vaults()
  getTokenLargestAccounts() → inspect vaults → resolve pool
  Used only if primary tx path finds nothing

Phase 6: LISTENER INTEGRATION (5 min)
  Read POOL_DETECTOR_DEBUG env var
  Pass debug flag to PoolDetector at init

Phase 7: HEALTH ENDPOINT STATS (10 min)
  Add detection metrics to /api/price/health
  primary_success, fallback_used, total_attempted

================================================================================
THE 7 FAILURE MODES (NOW ANSWERABLE)
================================================================================

Q1: Is tx really v0?
  Answer from: [POOL_DETECT] has_addressTableLookups=True/False

Q2: Are loaded addresses populated?
  Answer from: [POOL_DETECT] writable_loaded=X readonly_loaded=Y

Q3: What accounts in the tx?
  Answer from: [POOL_DETECT_DEBUG] idx=0...idx=N (one line per account)

Q4: Are any accounts AMM-owned?
  Answer from: [POOL_DETECT_DEBUG] amm_match=True/False (search for True)

Q5: Do candidates pass validation?
  Answer from: [POOL_DETECT] "invalid data_len=X (expected >= Y)"

Q6: Is pool PDA completely absent?
  Answer from: No "amm_match=True" anywhere in logs

Q7: Does fallback work?
  Answer from: [POOL_DETECT_FALLBACK] "succeeded" or "failed"
